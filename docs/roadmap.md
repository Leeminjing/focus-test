# 实施路线

当前已经可以封存目录，通过统一调度执行 Node/pytest，并查询持久化事件和结果。以下复选框只表示已实现及验证的部分；完整目标见 [design.md](design.md)。

## M0 输入封存与协议

- [x] 版本化真实执行请求，区分 Request、Job 和 Attempt。
- [x] 含未提交及 Git 忽略文件的 manifest、SHA-256 内容存储。
- [x] 两轮复制核验、变化拒绝、链接与越界拒绝、独立物化目录。
- [x] 环境和策略身份、规范化执行键；调用方不进入执行键。
- [x] 协议校验、幂等冲突、范围及版本边界，CLI 和 HTTP 链路。
- [x] 执行后复核声明输入，修改原始输入不能产生通过。

`verified_copy` 是实际复制字节的身份；原子工作区版本仍需 Focus 写屏障。环境依赖清单只描述已知输入，不能凭 lockfile 宣称运行器安装包已封存。

## M1 集中运行

- [x] 请求订阅与实际执行分离。
- [x] 完全相同模拟请求的在途合并及原始 Attempt 归属。
- [x] CPU/内存准入、同 Context FIFO、跨 Context 轮转、独占资源、老任务预留。
- [x] 取消和等待期限只影响当前订阅，最后一个订阅离开才取消 Job。
- [x] 带序号和校验的追加事件日志、同步落盘及终态恢复。
- [x] 新请求不复用已完成结果，幂等重试保留原请求身份。

真实 Node/pytest 暂时只允许 `reuse_policy: none`，避免对外部安装包、原生库等未闭合依赖做错误复用。已验证的在途复用负载为自带确定性模拟器。

## M2 生命周期可靠性

- [x] Windows 在测试代码恢复执行前绑定 Job Object，取消和超时清理整个 Job。
- [x] POSIX 进程组实现，Linux 后代收养与回收；本机尚未实跑这些平台。
- [x] 启动意图先落盘、单实例 OS 锁、重启不重放未结算任务。
- [x] 未确认真实清理时保留 unknown 并隔离新调度。
- [x] 带校验证据、记录和日志观测配额、分页读取；慢客户端不阻塞日志生产。
- [x] 挂起、子进程、取消、报告损坏/截断、输出洪泛及证据配额测试。
- [ ] 自动保留和垃圾回收策略，保证验收引用不被删除。
- [ ] 真实磁盘满、同步失败、Windows 服务崩溃场景的故障注入。
- [ ] Linux/macOS 实跑与 race detector 结果；目前提供 CI 配置和交叉构建检查。

## M3 真实测试适配

- [x] Node 24 内置测试 reporter，准确显式文件范围、早失败和闭合报告。
- [x] pytest 收集、setup、call、teardown 与 session 结算。
- [x] teardown/setup 失败、收集错误、零用例不能误判通过。
- [x] 真实进程的输入绑定、清理确认、原工作区不被修改。
- [x] 本地凭据保护执行接口，拒绝未实现的沙箱策略及额外运行参数。

pytest 当前单进程，Node 按声明 workers 执行；环境描述覆盖可执行文件、脚本和环境变量，真实依赖闭包尚未完成，因此不开放真实用例共享或通过结果缓存。

## M4 Focus 接入

- [x] 提供标准库实验客户端和身份、权限、证据采纳合同。
- [x] 客户端鉴权、游标读取、原始执行身份保留的传输测试。
- [ ] 在 Focus 本体增加受治理测试工具及执行代理。
- [ ] slot、revision、snapshot 的可信绑定与短时封存屏障。
- [ ] 测试事件进入 inbox，记录模型实际消费回执。
- [ ] 原始执行与 ResultAdoption 分别持久化。
- [ ] CompletionSourceValidator 专用来源检查和最终组合快照验证。

本仓库尚未部署进 Focus，`focus-broker` 会拒绝执行。实验客户端不能替代以上接入工作，也不能让本地结果直接满足 Focus 完成验收。

## M5 收益实验

- [x] 1、2、4、8 Context 固定预算的模拟重放。
- [x] 关闭复用与在途复用的实际 Job 数及耗时对照。
- [x] 单独记录冷/暖内容存储封存成本，保存原始 JSON。
- [ ] 同代码版本下重复采样并报告分布。
- [ ] 真实项目、部分重叠和不同脏工作区负载。
- [ ] CPU 时间、进程集合峰值内存、准备阶段和模型消费时间。
- [ ] 完成结果缓存、增量选择与环境热复用的收益决策。

现有单次模拟数据验证协调机制；不据此声称真实 Focus 已获得同等加速。
