# 实施路线

本地初始化阶段已提供可编译、可启动、可验证的模拟链路，属于 M0 的基础部分。完整设计见 [design.md](design.md)，功能声明以本页及 README 为准。

## 初始化

- [x] 本地 Git `main` 分支与 Go 模块。
- [x] 零第三方依赖的 CLI 和服务入口。
- [x] 内置模拟用例及独立任务状态。
- [x] 幂等提交、事件游标、结果查询与关闭服务时取消。
- [x] 输入边界、并发重试、提前失败和 CLI 到 HTTP 服务的行为测试。
- [x] 跨平台 CI 配置；实际远程运行需仓库推送后验证。
- [x] 原始架构、设计基线、协议说明和开发约束。

## M0 输入封存与协议

- [ ] 定义真实执行请求与请求身份，区分 Request、Job 和 Attempt。
- [ ] 实现含未提交文件的封存 manifest 及内容存储。
- [ ] 输入不稳定时拒绝执行；物化独立工作目录。
- [ ] 定义环境与策略身份，并形成规范化执行键。
- [ ] 为实际执行协议提供错误、范围和版本兼容合同。

模拟接口保持在 `/v1/fixture-jobs`。真实任务接口必须携带快照、环境与执行策略，不能复用模拟请求来绕开封存。

## M1 集中运行

- [ ] 请求订阅与实际执行分离。
- [ ] 完全相同的在途请求合并。
- [ ] 资源准入、公平队列与独占资源。
- [ ] 独立取消订阅，不影响其他合法订阅者。
- [ ] 追加事件日志及终态持久化。

## M2 生命周期可靠性

- [ ] 平台进程树管理及清理回执。
- [ ] 启动意图、重启恢复与单实例边界。
- [ ] 日志背压、配额、损坏检测和保留策略。
- [ ] 挂起、磁盘满、断线、报告截断和启动中断验证。

## M3 真实测试适配

- [ ] Node 测试 reporter。
- [ ] pytest 收集、setup、call、teardown 与 session 结算。
- [ ] 准确范围、零用例、失败与报告闭合验证。

## M4 Focus 接入

- [ ] 测试工具和受治理的执行代理。
- [ ] slot、revision、snapshot 与调用方绑定。
- [ ] 失败事件进入 Agent 的下一次模型决策。
- [ ] 原始执行与 ResultAdoption 分别存储。
- [ ] 完成验收专用来源检查及最终组合快照验证。

## M5 收益实验

- [ ] 1、2、4、8 Context 的模拟与真实负载重放。
- [ ] 相同预算下分别测量调度、在途去重及结果缓存。
- [ ] 记录快照成本、资源消耗、失败到模型消费时间与错误复用。
- [ ] 根据实测结果决定是否投入增量选择与环境热复用。
